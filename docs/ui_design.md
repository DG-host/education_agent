# 智慧学伴 · 教研工作台 UI 设计说明

> 版本：ui/1.0（仓库 v0.7.0）
> 定位：把已有 9 步智能体流水线的机器产物，变成教师可浏览、可核对、可演示的本地工作台。
> 原则：**只读快照、零前端构建、零图表库、不展示学生作答原文与参考答案。**

## 1. 目标与非目标

### 1.1 要解决的问题

流水线已经能产出 `out/content_map.json`、`out/diagnosis_all.json`、`out/recommendations_all.json` 等 18 个文件，但评委和教师不可能直接读 JSON。工作台要回答四个问题：

1. 这次分析覆盖了多少学生、多少记录、修了哪些数据？
2. 某个学生现在什么水平，弱项有没有足够证据？
3. 三类典型案例的“学习要求—已有表现—学习建议”能否逐条回到材料与记录？
4. 结论是怎么跑出来的，失败时能不能定位？

### 1.2 非目标

- 不做账号、权限、多用户协作；
- 不做在线编辑、批注回写、数据库；
- 不替代 `run.cmd` 的契约与守卫，UI 不产生新的分析口径；
- 不引入 npm / Vite / React / ECharts 等构建链或图表库；
- 不在页面渲染学生作答原文、参考答案、真实个人信息。

## 2. 运行形态

```text
双击 run_ui.cmd
  └─ powershell -File run.ps1 -Task ui
       └─ python src/ui_server.py
            ├─ 127.0.0.1:8765（被占用则 8766…8775 自动顺延）
            ├─ 静态文件 ui/index.html + ui/css + ui/js
            └─ 只读 out/ 与 data/derived/作答记录_清洗版.csv
```

- 仅监听回环地址，不对外网开放；
- 启动后自动打开默认浏览器；`--no-browser` 可关闭，`--port 0` 可随机端口；
- 后端除可选的教学咨询依赖 `openai` 外，只用 Python 标准库（`http.server`、`json`、`csv`、`subprocess`、`threading`），无需其他 pip 包；
- 前端为原生 ES Module，浏览器直接加载，无打包步骤；
- 分析数据不落库，刷新页面即重新读取快照；仅“数据录入”页把录入副本写入 `data/input/`（打包态写 `%LOCALAPPDATA%\SmartCompanion\input`）；咨询对话只存在浏览器内存。

## 3. 信息架构

固定七项主导航，对应赛题三项任务、数据治理、录入与可选教学咨询：

| 导航 | 路由 | 回答的问题 | 主要数据源 |
| --- | --- | --- | --- |
| 总览 | `#/overview` | 这次分析的整体规模、班级差异、共性弱项、案例入口 | 快照 `meta`、`diagnosis`、`cases`、`qc`、`clean` |
| 学生画像 | `#/students`、`#/students/D03` | 个体表现、节点覆盖、9 项指标、建议与证据 | `diagnosis`、`recommendations`、清洗版记录 |
| 典型案例 | `#/cases`、`#/cases/D03` | 三类学习需求的对照案例与班级参照 | `cases`、`diagnosis`、`recommendations`、`content_map` |
| 内容图谱 | `#/content` | 3 主题 × 9 指标 × 65 材料的要求与出处 | `content_map` |
| 数据质量 | `#/quality` | 质检、清洗、守卫、9 步轨迹、产物哈希 | `qc`、`clean`、`guard`、`trace` |
| 数据录入 | `#/input` | 粘贴/上传与作答记录同构的 14 列 CSV，校验、保存、导出 | `/api/records`、`data/input/` |
| 教学咨询 | `#/consult` | 向 DeepSeek 提问；可选带入某学生聚合诊断 | `/api/consult`、诊断/建议/内容图谱 |

全局元素：

- 左侧深青侧栏：品牌、七项导航、快照时间、学生/班级数、“查看运行轨迹与口径”；
- 顶栏：页面标题、全局搜索、快照时间 chip、刷新、重新分析；
- 主区：页头 + 卡片网格；窄屏折叠为顶部横向导航；
- 右侧抽屉：材料、指标、记录的详情，不跳页；
- 页脚：数据使用边界与版本号 `ui/1.0`。

## 4. 视觉规范

### 4.1 设计 token

| 用途 | 变量 | 色值 |
| --- | --- | --- |
| 页面底色 | `--bg` | `#F4F7F7` |
| 品牌主色 | `--brand` | `#0F766E` |
| 深色侧栏/标题 | `--brand-deep` | `#0B4F4A` |
| 强调/警示 | `--accent` | `#D97706` |
| 通过/正向 | `--ok` | `#15803D` |
| 风险/负向 | `--bad` | `#BE123C` |

- 字体：系统 UI 字体栈，正文 13–14px，表格 11.5–13px，KPI 数字 24–30px；
- 卡片：白底、14px 圆角、1px 浅边、轻阴影；
- 语义色只表达状态，不用于装饰；同一指标在诊断、案例、建议中颜色一致；
- 图标为内联 SVG（16×16），不使用图标字体或外链。

### 4.2 图表替代方案

不引入图表库，用原生 CSS/SVG 完成：

- KPI：数字 + 说明 + 细进度条；
- 班级对比：双列卡片 + 水平条；
- 指标热力图：3×3 网格，按满分率着色，格内显示百分比与置信度徽标；
- 学生得分：SVG 圆环（`stroke-dasharray`）；
- 建议顺序：左侧编号圆点 + 竖向连接线；
- 知识网络：原生 SVG，确定性三列布局（主题→指标→课标），材料层按需展开；边只画显式出处；
- 质量页：步骤时间线 + 状态徽标。

### 4.3 响应式与打印

断点：`1400px`（知识网络详情移到画布下方）、`1240px`（侧栏收窄）、`1080px`（双列）、`900px`（单列）、`680px`（移动端导航与头部重排）。

- 所有 grid/flex 子项显式 `min-width: 0`，禁止被长表格撑破页面；
- 宽表（如班级参照）在窄屏用 `.table-compact`，或由卡片内部横向滚动；
- 390px 宽度下页面 `scrollWidth == clientWidth`，不出现整页横向滚动；知识网络例外：画布自身横向滚动（`#graphSvg min-width: 860px`），不撑破页面；
- `@media print` 隐藏侧栏、顶栏按钮与页脚，保留标题、卡片、表格与证据链；知识网络打印时隐藏工具栏与详情，保留画布（最高 640px）、图例与出处说明；
- 支持 `prefers-reduced-motion`，关闭非必要动画。

## 5. 页面与数据映射

### 5.1 总览

| 区块 | 展示 | 字段 |
| --- | --- | --- |
| Hero | 快照时间、四任务闭环说明、数据范围 | `meta.generated_at`、`students`、`groups`、`records`、`unique_events`、`anomalies`、`changes`、`recommendations` |
| KPI 六卡 | 覆盖学生、作答记录、异常与修正、个性化建议、典型案例、内容图谱 | `meta.*` |
| 班级对比 | 两班平均得分率/覆盖率、差值、指标最大差异 | `group_level.by_class`、`class_comparison` |
| 共性弱项 | 群体满分率最低的 3 个指标（观测数 ≥ 10） | `group_level.by_indicator` |
| 指标热力图 | 3 主题 × 3 指标，颜色越暖满分率越低 | `by_indicator` + `content_map` |
| 典型案例 | 三角色卡片，点击进详情 | `cases[]` |
| 运行与质量 | 质检异常、修正处数、守卫 5 类、9 步流水线 | `qc`、`clean`、`guard`、`trace` |

### 5.2 学生画像

列表页：

- 40 张学生卡，按班级/标记/得分率/覆盖度筛选，按学生编号或得分率排序；
- 每卡显示：记录数、节点覆盖、整体得分率、前两个弱项、风险标记（数据不足/覆盖偏低/有未作答/待评分）；
- 得分率用圆环 + 百分比，弱项用红条，覆盖度用细条。

详情页：

1. 头部：学生编号、班级、记录数、节点覆盖、班级均值、已评/待评、建议条数、风险标记；
2. 节点与指标：N01/N02 覆盖与得分率；9 项指标逐项显示观测数、满分数、满分率、置信度；
3. 个性化建议：按 `seq` 排序，显示材料、动作（回顾/练习/变式/观察）、提示级别、理由、证据 chip、观察点、调整条件；
4. 本轮不推荐：说明为什么暂不安排某些材料；
5. 复测安排：何时、用什么材料、达到什么阈值进入下一步；
6. 判断依据：记录数、覆盖率、重点指标、与班级均值差；
7. 班级参照：该生得分率 vs 班级均值，差值以 pp 显示；
8. 作答记录：只显示记录编号、材料、节点、修订、评分状态、得分/满分，**不显示作答原文与参考答案**；
9. “怎么读这一页”：解释得分率、满分率、低置信的含义。

### 5.3 典型案例

列表页：

- 三个角色：需要巩固（D03）、数据不足（D17）、稳定表现（D36）；
- 每卡显示选择理由、已评记录、节点覆盖、角色色；
- 两班对照卡：平均得分率、平均覆盖率、记录数、与对照班差值；
- 班级 × 指标对比表：9 行 × DC01/DC02/差值，差值 ≥ 10pp 标记为需关注。

详情页：

- 顶部角色、学生、班级、整体得分率、已评、覆盖；
- 主区按建议顺序展开三列：**学习要求**（课标条目/PDF 页/正文页/教材页）、**已有表现**（观测数、满分数、满分率、置信度、证据记录）、**学习建议**（材料、动作、提示级别、理由、观察点、调整条件）；
- 右侧：诊断摘要（需要巩固/稳定表现）、班级参照（紧凑表）、适用范围；
- 打印按钮只保留案例主体。

### 5.4 内容图谱

#### 5.4.1 知识网络（`#/content` 顶部）

- 投影来源：`build_snapshot()` 调用 `graph_model.build(content_map)`，只把显式关系变成节点和边，不读 PDF、不做语义相似度；
- 节点 72 个：3 主题 + 9 指标 + 3 课标 + 57 份被指标引用的材料；8 份教材切片 B01–B08 未标主题/指标，进入 `meta.excluded_materials`，不画；
- 边 83 条：9 条主题→指标、9 条指标→课标、63 条指标→材料、2 条主题递进；骨架 15 节点 / 20 边；
- 默认骨架：只画主题、指标、课标；点“显示材料”后展开 57 个材料节点，可再收起；
- 布局：确定性三列，主题 y=96、指标 y=300、课标 y=540；主题 x=166/500/834，指标围绕主题 ±108，材料围绕主指标半径 54；不使用 `Math.random` 或力导向，双跑位置一致；
- 交互：搜索主题/指标/材料、选中节点高亮上下游、只看相邻、按群体满分率着色、缩放/适配/全屏、拖拽平移、键盘 Tab/Enter；
- 详情面板：节点名称、类型、所属主题、课标/材料出处、群体满分率、观测/满分、关系列表；指标/材料可直接打开既有抽屉；
- 图例与脚注：实线=显式出处、虚线=学习进阶；“材料层 57 份”“8 份教材切片未挂接”。

#### 5.4.2 主题与材料

- 主题递进提示：T01 → T02 → T03；
- 3 个主题卡片，每个含 3 个指标卡：指标编号、名称、观察描述、课标编号、PDF 页、正文页、教材页、群体满分率、观测数、材料 chip；
- 材料索引：65 份材料可按类型筛选，表格列含材料、类型、主题、题型、满分、可用节点、对应指标；
- 点击材料/指标打开抽屉，抽屉内列出关联记录数与材料说明；材料抽屉不展示参考答案。

### 5.5 数据质量

- 六张 KPI：原始记录、折叠修订、质检异常、修正字段、清洗后异常、守卫；
- 9 步流水线时间线：工具名、序号、状态、耗时、摘要、产物链接；
- 守卫层 5 类检查：学生覆盖、证据可解析、置信度不变量、答案与合规、个人信息；
- 质检异常列表：记录编号、学生、材料、规则编号、说明；
- 契约与版本：content_map / diagnosis / recommendation / batch / ui.snapshot；
- 限制与适用范围：跨节点不可比、记录为抽样、群体结论边界；
- 产物与哈希：9 个来源文件的路径、SHA256 前缀、字节数。

## 6. 交互设计

| 交互 | 行为 |
| --- | --- |
| 导航 | hash 路由，浏览器前进/后退可用；未知路由显示 404 卡片 |
| 全局搜索 | 140ms 防抖，匹配学生编号、指标、材料、记录；保留输入焦点；Enter 精确学生号直达详情 |
| 材料/指标/记录 chip | 打开右侧抽屉；Escape 关闭并归还焦点 |
| 刷新 | 重新 `GET /api/snapshot`，不重跑流水线 |
| 重新分析 | `POST /api/run`，按钮进入“分析中…”，每 1200ms 轮询状态；成功后自动刷新，失败自动打开日志抽屉 |
| 打印 | 案例/内容/质量页提供打印按钮，调用 `window.print()` |
| 知识网络 | 搜索/展开材料/按满分率着色/缩放/适配/全屏；点节点或 Tab+Enter 选中，Esc 清除；拖拽平移；详情内可打开材料/指标抽屉 |
| 错误页 | 503 时列出缺失产物与 `run.cmd all` 提示，提供“运行分析/重试” |

## 7. 后端接口

所有 API 返回 UTF-8 JSON，`Cache-Control: no-store`；静态资源 `no-cache`。

| 方法 | 路径 | 成功 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/health` | 200 | `{ok, version, port, snapshot_at, artifacts_ready, missing[]}`，用于启动探活 |
| GET | `/api/snapshot` | 200 | 一次性返回 UI 所需快照；缺核心产物时 503 |
| GET | `/api/run/status` | 200 | `{state, started_at, finished_at, exit_code, log_tail[]}` |
| POST | `/api/run` | 202 | 启动 9 步流水线；已在运行返回 409 |
| GET | `/api/consult/status` | 200 | 脱敏咨询配置状态；未配置时 `configured=false` |
| POST | `/api/consult` | 200 | 教学咨询；请求体上限 64 KB，具体错误码见 `docs/consult_interface.md` |
| GET | `/`、`/css/*`、`/js/*` | 200 | 静态文件 |

### 7.1 快照结构（`ui.snapshot/1`）

```json
{
  "schema_version": "ui.snapshot/1",
  "ui_version": "ui/1.0",
  "generated_at": "…",
  "meta": {"students": 40, "groups": 2, "records": 806, "unique_events": 799,
            "anomalies": 7, "changes": 10, "recommendations": 135,
            "cases": 3, "topics": 3, "indicators": 9, "materials": 65,
            "graph_nodes": 72, "graph_edges": 83, "graph_resources": 57},
  "sources": [{"name": "content_map", "path": "out/content_map.json", "sha256": "…", "bytes": 0}],
  "docs": {"content": {}, "diagnosis": {}, "recommendations": {}, "cases": {},
            "qc": {}, "clean": {}, "guard": {}, "trace": {}},
  "graph": {"version": "content_graph/1", "nodes": [], "edges": [],
            "meta": {"node_counts": {}, "edge_counts": {}, "skeleton_nodes": 15,
                     "skeleton_edges": 20, "resources": 57, "excluded_materials": []}},
  "records": [{"record_id": "DR0001", "student_id": "D01", "material_id": "Q…",
                "topic_id": "T01", "node_id": "N01", "revision": 1,
                "submitted_at": "…", "status": "已评分", "score": 3, "max_score": 3}],
  "warnings": []
}
```

- `records` 只保留 10 个白名单字段，**不含**学生最终作答、解答过程、评分点得分；
- `guard`、`trace` 为可选；缺失时降级为 `null` 并写 `warnings`；
- 核心产物 7 个：`content_map.json`、`diagnosis_all.json`、`recommendations_all.json`、`cases.json`、`qc_report.json`、`clean_report.json`、清洗版 CSV；
- `graph` 由 `content_map` 纯投影得到，不新增 `out/` 文件；旧快照没有该字段时，内容页显示“当前快照没有知识网络”，其余页面正常。

### 7.2 错误结构

```json
{"error": {"code": "artifacts_missing", "message": "…", "details": {"missing": ["…"], "hint": "run.cmd all"}}}
```

| HTTP | code | 页面行为 |
| --- | --- | --- |
| 400 | `bad_request` | 提示请求参数错误 |
| 403 | `forbidden` | 提示只允许本机工作台发起运行 |
| 404 | `not_found` | API 返回 JSON；静态资源显示 404 |
| 409 | `already_running` | 继续轮询，不重复启动 |
| 503 | `artifacts_missing` | 缺失产物卡片 + 运行/重试按钮 |
| 503 | `consult_unconfigured` / `consult_unavailable` | 咨询页显示配置路径/缺库提示，发送禁用 |
| 409 | `consult_busy` | 咨询页提示上一请求仍在进行 |
| 500 | `read_failed` / `snapshot_failed` | 显示错误码与重试 |

## 8. 安全与数据边界

1. **仅回环**：绑定 `127.0.0.1`；Host 必须是 `127.0.0.1:<port>` 或 `localhost:<port>`；
2. **写操作三重校验**：`POST /api/run` 必须同源 Origin、合法 Host、`X-DSH-UI: 1`；
3. **CSP**：`default-src 'self'`，脚本仅同源，禁止 `object-src`、`frame-ancestors`；
4. **防路径穿越**：静态路径经 `realpath` 校验必须位于 `ui/` 下；
5. **数据最小化**：记录只暴露评分与定位字段；不展示作答原文、参考答案、评分点明细；
6. **无个人信息**：赛题数据只有学生编号与模拟班级；守卫额外扫描手机号、邮箱、18 位身份证；
7. **只读优先**：UI 不直接改 `out/`；只有用户点击“重新分析”才调用既有流水线，且仍走 clean/content/qc/diagnose/recommend/guard/cases/report/validate 九步。

## 9. 失败与空态

| 场景 | 表现 |
| --- | --- |
| 首次启动、`out/` 为空 | 503 错误页，列出 7 个缺失产物，提示 `run.cmd all` |

## 10. 可访问性与打印

- 语义化 `header/nav/main/section`，每页一个 `h1`；

- 尊重 `prefers-reduced-motion`。

## 12. 已知边界与后续

- 当前快照一次性加载 806 条记录，数据量再大（>5 万条）需要分页或按需接口；
- 重跑为单实例后台进程，不做队列与并发；
- 不提供账号体系，适合本地演示与单机复核；
- 源码态用 `run_ui.cmd`；打包态用 `dist\智慧学伴.exe`（单文件，内嵌只读快照，录入写用户目录）；
- 视觉上仍以表格与卡片为主，若答辩需要，可另做一页“讲解模式”大字号投屏，不影响现有七页；
- 公开演示是 `demo/` 静态快照，不连后端，更新数据后需重新生成并推送；其脱敏只覆盖 `snapshot.json`，不改变仓库其他目录的可见性。
- 知识网络只投影 `content_map` 的显式关系，不抽取 PDF 正文、不做语义相似度；教材切片未标主题/指标时不猜测挂接。
