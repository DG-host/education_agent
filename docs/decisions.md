# 决策记录（ADR）

> 只记录“改变了做法”的决定：背景 → 决定 → 理由 → 代价。新增条目追加在末尾，不改历史条目。
> 契约冻结版本：`0.1.0`（`schemas/*.schema.json` 的 `schema_version` 与之绑定）。

## D1 仓库与赛题资料分离
- **背景**：赛题原始数据要反复引用，但一旦被脚本改写就失去唯一真相。
- **决定**：`data/raw/` 只放原始副本 + `SHA256SUMS.txt`；一切派生数据进 `data/derived/`，一切机器产物进 `out/`。
- **理由**：评委复核与内部回归都要求“同一个输入哈希 → 同一个结果”；`run.ps1` 第 4 步直接校验哈希。
- **代价**：改数据必须走“新副本 + 变更记录”，不能就地改。

## D2 列名保留中文，口径常量集中
- **背景**：赛题字段全是中文表头，重命名会让“字段说明 ↔ 数据”对照断链。
- **决定**：读写全程沿用中文列名；列名/状态值/正则集中在 `src/common.py`，业务代码不写字面量。
- **理由**：字段说明.csv 是交付物的一部分，列名即接口。
- **代价**：Python 代码里中文键偏多，靠 `COLUMNS` 常量兜底。

## D3 修订版本取最高
- **背景**：806 行里有 799 个唯一 `作答事件编号`，7 个事件存在 `修订版本=2`。
- **决定**：按事件折叠，取最高版本参与统计；被折叠的行数写进 `revisions_folded`。
- **理由**：v2 是学生复核后的最终态（D01 的 DR0018→DR0023 即 Q043 由“待评分”变“已评分 1/3”）。
- **代价**：折叠逻辑必须可核对，故 `out/tables/anomalies.csv` 保留原始行号。

## D4 清洗只改“矛盾的总分”，不改学生答案
- **背景**：DR0361 得 10 分但满分 1、评分点和 10≠1；DR0133 总分 3 而评分点和 2。
- **决定**：以评分点明细为准下调总分；学生作答原文不动；每处改动进变更记录。
- **理由**：评分点是过程性证据，总分是汇总值；改答案会污染“学生真实表现”。
- **代价**：清洗版与原始版必须成对保留，质检要能分别跑（D5）。

## D5 质检读原始版，诊断读清洗版
- **背景**：若诊断直接吃原始版，DR0361 的 10/1 会把节点得分率推到 1.125，触发 schema `maximum: 1`。
- **决定**：`qc.py` 默认读 `data/raw/作答记录.csv` 出异常清单；`build_diagnosis` 固定读 `data/derived/作答记录_清洗版.csv`；`baseline.json` 同时记录 before/after。
- **理由**：一份数据两种用途——质检要“看见脏”，诊断要“用干净的”。
- **代价**：两个入口必须同时绿，`run.cmd` 的 1/4 步同时断言 7 与 0。

## D6 覆盖度分母 = 节点可用题目数
- **背景**：每生每节点只有 4–17 条记录，题目是抽样作答；用 54 题（全部）做分母会系统性低估。
- **决定**：`coverage[node] = 观测材料数 / 该节点可用题目数`，同时输出 `union`（54 题）口径作对照。
- **理由**：N02 已包含 N01 的题目（27/45），分母取节点自己的集合才可比。
- **代价**：跨节点覆盖度不能直接相加，报告里必须写清分母。

## D7 置信度阈值 5 / 10
- **背景**：多数指标只有 1–4 条观测，直接给百分比等于过度解读。
- **决定**：`MIN_N_FOR_CONFIDENCE = 5`；n<5 低、5≤n<10 中、n≥10 高；低置信结论进 `notes`。
- **理由**：赛题原文“缺少记录不等于答错或未掌握”，阈值是把这句话变成代码。
- **代价**：首版诊断里大量 `low`，需要在建议侧用“补观察”承接（D11 的 `observe`）。

## D8 三份契约 v0.1.0，失败即阻断
- **背景**：三人并行时，口头约定会在第二天漂移。
- **决定**：draft-07、`additionalProperties: false`、必填字段显式列出；`validate.py` 失败打印 JSON Pointer 并非 0 退出。
- **理由**：机器可读的“不许加字段”比会议纪要可靠；Pointer 让定位从“翻文件”变成“跳转”。
- **代价**：加字段必须先改 schema 并升版本，所有产出同步重跑。

## D9 材料编号沿用赛题原始编号
- **背景**：材料表有 65 行，题目/教材/学习卡混排。
- **决定**：题目 `Q001–Q054`、教材 `B01–B08`、学习卡 `L01–L03`，不新建内部编码。
- **理由**：`作答记录` 的 `材料编号` 与评分点前缀（`Q017P1`）都基于原始编号，重编码等于自断外键。
- **代价**：编号长度不一（4 位/3 位），schema 用 `^(Q\\d{3}|[BL]\\d{2})$` 兜住。

## D10 教材切片未标主题 → 输出 null，不猜
- **背景**：8 份教材的 `主题编号` 为空，强行归属会污染“材料依据”这一评分项。
- **决定**：`materials_index[].topic_id = null`，并在 `open_questions` 与 `content_matrix_draft.csv` 的“需人工复核”列标记。
- **理由**：评分标准里“材料依据”要可追溯；猜出来的归属经不起追问。
- **代价**：第一天留 8 条待办给 A，内容地图的“范围覆盖”暂时不完整。

## D11 建议动作四值 + 提示分级不含“直接给答案”
- **背景**：赛题要求“提示不直接给答案”，且要“便于教师调整”。
- **决定**：`action ∈ {review, practice, variant, observe}`；`hint_level ∈ {提示, 分步提示, 不给答案}`；每条建议必须带 `evidence_refs`（≥1）与 `adjust_condition`。
- **理由**：把“为什么推这道题”和“什么时候换策略”写进结构，答辩时可逐条点开。
- **代价**：没有证据的建议写不出来——这正是想要的效果。

## D12 文件所有权与“先改契约”
- **背景**：三人并行最容易出现的不是写不出代码，而是互相覆盖。
- **决定**：A 拥有 `content_map.py` + 内容地图产物；B 拥有 `qc.py`/`validate.py` + `data/derived/`；C 拥有 `run.ps1`/`run.cmd`/`examples/`/文档。跨文件改动先提契约变更（schema 版本 + 影响面），再各自落地。
- **理由**：与`附录 A3` 的文件所有权表一致；冲突从“合并代码”前移到“评审契约”。
- **代价**：每天固定 30 分钟契约评审（17:30），雷打不动。

## D13 自检内置“零硬编码编号”断言
- **背景**：隐藏评测集是 10–20 名学生、100–400 条记录，字段口径相同。
- **决定**：`run.ps1` 第 4 步用正则扫 `src/*.py`，出现 `D0x/Q0xx/T0x/N0x/DRxxxx` 字面量即失败。
- **理由**：硬编码在开发集上看不出问题，换数据就崩；让 CI 替人记住这件事。
- **代价**：源码里的示例文案要用数据现算（`node_note()` 即为此而生）。
