# 决策记录（ADR）

> 只记录“改变了做法”的决定：背景 → 决定 → 理由 → 代价。新增条目追加在末尾，不改历史条目。
> 契约冻结版本：`0.1.0`（`schemas/*.schema.json` 的 `schema_version` 与之绑定）。

## D1 仓库与赛题资料分离
- **背景**：赛题原始数据要反复引用，但一旦被脚本改写就失去唯一真相。
- **决定**：`data/raw/` 只放原始副本 + `SHA256SUMS.txt`；一切派生数据进 `data/derived/`，一切机器产物进 `out/`。
- **理由**：评委复核与内部回归都要求“同一个输入哈希 → 同一个结果”；`run.ps1` 的 selfcheck 阶段直接校验哈希。
- **代价**：改数据必须走“新副本 + 变更记录”，不能就地改。

## D2 列名保留中文，口径常量集中
- **背景**：赛题字段全是中文表头，重命名会让“字段说明 ↔ 数据”对照断链。
- **决定**：读写全程沿用中文列名；列名/状态值/正则集中在 `src/common.py`，业务代码不写字面量。
- **理由**：字段说明.csv 是交付物的一部分，列名即接口。
- **代价**：Python 代码里中文键偏多，靠 `COLUMNS` 常量兜底。

## D3 修订版本取最高
- **背景**：806 行里有 799 个唯一 `作答事件编号`，7 个事件存在 `修订版本=2`。
- **决定**：按事件折叠，取最高版本参与统计；被折叠的行数写进 `revisions_folded`。
- **理由**：v2 是学生复核后的最终态（D01 的 DR0018→DR0023 即 Q043 由“待评分”变“已评分 1/3”）。
- **代价**：折叠逻辑必须可核对，故 `out/tables/anomalies.csv` 保留原始行号。

## D4 清洗只改“矛盾的总分”，不改学生答案
- **背景**：DR0361 得 10 分但满分 1、评分点和 10≠1；DR0133 总分 3 而评分点和 2。
- **决定**：以评分点明细为准下调总分；学生作答原文不动；每处改动进变更记录。
- **理由**：评分点是过程性证据，总分是汇总值；改答案会污染“学生真实表现”。
- **代价**：清洗版与原始版必须成对保留，质检要能分别跑（D5）。

## D5 质检读原始版，诊断读清洗版
- **背景**：若诊断直接吃原始版，DR0361 的 10/1 会把节点得分率推到 1.125，触发 schema `maximum: 1`。
- **决定**：`qc.py` 默认读 `data/raw/作答记录.csv` 出异常清单；`build_diagnosis` 固定读 `data/derived/作答记录_清洗版.csv`；`baseline.json` 同时记录 before/after。
- **理由**：一份数据两种用途——质检要“看见脏”，诊断要“用干净的”。
- **代价**：两个入口必须同时绿，`run.cmd` 的 selfcheck 阶段同时断言 7 与 0。

## D6 覆盖度分母 = 节点可用题目数
- **背景**：每生每节点只有 4–17 条记录，题目是抽样作答；用 54 题（全部）做分母会系统性低估。
- **决定**：`coverage[node] = 观测材料数 / 该节点可用题目数`，同时输出 `union`（54 题）口径作对照。
- **理由**：N02 已包含 N01 的题目（27/45），分母取节点自己的集合才可比。
- **代价**：跨节点覆盖度不能直接相加，报告里必须写清分母。

## D7 置信度阈值 5 / 10
- **背景**：多数指标只有 1–4 条观测，直接给百分比等于过度解读。
- **决定**：`MIN_N_FOR_CONFIDENCE = 5`；n<5 低、5≤n<10 中、n≥10 高；低置信结论进 `notes`。
- **理由**：赛题原文“缺少记录不等于答错或未掌握”，阈值是把这句话变成代码。
- **代价**：首版诊断里大量 `low`，需要在建议侧用“补观察”承接（D11 的 `observe`）。

## D8 单生契约 v0.1.0（+ 建议批次），失败即阻断
- **背景**：三人并行时，口头约定会在第二天漂移。
- **决定**：draft-07、`additionalProperties: false`、必填字段显式列出；`validate.py` 失败打印 JSON Pointer 并非 0 退出。
- **理由**：机器可读的“不许加字段”比会议纪要可靠；Pointer 让定位从“翻文件”变成“跳转”。
- **代价**：加字段必须先改 schema 并升版本，所有产出同步重跑。

## D9 材料编号沿用赛题原始编号
- **背景**：材料表有 65 行，题目/教材/学习卡混排。
- **决定**：题目 `Q001–Q054`、教材 `B01–B08`、学习卡 `L01–L03`，不新建内部编码。
- **理由**：`作答记录` 的 `材料编号` 与评分点前缀（`Q017P1`）都基于原始编号，重编码等于自断外键。
- **代价**：编号长度不一（4 位/3 位），schema 用 `^(Q\\d{3}|[BL]\\d{2})$` 兜住。

## D10 教材切片未标主题 → 输出 null，不猜
- **背景**：8 份教材的 `主题编号` 为空，强行归属会污染“材料依据”这一评分项。
- **决定**：`materials_index[].topic_id = null`，并在 `open_questions` 与 `content_matrix_draft.csv` 的“需人工复核”列标记。
- **理由**：评分标准里“材料依据”要可追溯；猜出来的归属经不起追问。
- **代价**：第一天留 8 条待办给 A，内容地图的“范围覆盖”暂时不完整。

## D11 建议动作四值 + 提示分级不含“直接给答案”
- **背景**：赛题要求“提示不直接给答案”，且要“便于教师调整”。
- **决定**：`action ∈ {review, practice, variant, observe}`；`hint_level ∈ {提示, 分步提示, 不给答案}`；每条建议必须带 `evidence_refs`（≥1）与 `adjust_condition`。
- **理由**：把“为什么推这道题”和“什么时候换策略”写进结构，答辩时可逐条点开。
- **代价**：没有证据的建议写不出来——这正是想要的效果。

## D12 文件所有权与“先改契约”
- **背景**：三人并行最容易出现的不是写不出代码，而是互相覆盖。
- **决定**：A 拥有 `content_map.py` + 内容地图产物；B 拥有 `qc.py`/`validate.py` + `data/derived/`；C 拥有 `run.ps1`/`run.cmd`/`examples/`/文档。跨文件改动先提契约变更（schema 版本 + 影响面），再各自落地。
- **理由**：与`附录 A3` 的文件所有权表一致；冲突从“合并代码”前移到“评审契约”。
- **代价**：每天固定 30 分钟契约评审（17:30），雷打不动。

## D13 自检内置“零硬编码编号”断言
- **背景**：隐藏评测集是 10–20 名学生、100–400 条记录，字段口径相同。
- **决定**：`run.ps1` 的 selfcheck 阶段用正则递归扫 `src/**/*.py`，出现 `D0x/Q0xx/T0x/N0x/DRxxxx` 字面量即失败。
- **理由**：硬编码在开发集上看不出问题，换数据就崩；让 CI 替人记住这件事。
- **代价**：源码里的示例文案要用数据现算（`node_note()` 即为此而生）。

## D14 智能体用顺序计划 + 工具注册表，不引入 DAG 调度
- **背景**：三项任务天然有先后，9 个能力大多线性依赖；三人协作需要一个能说清“谁先谁后、产物从哪来”的壳。
- **决定**：每个能力注册为 `ToolSpec(name, description, handler, consumes, produces, evidence)`；`PlanStep(tool, why)` 顺序执行；调用前检查前置产物，调用后检查声明产物并记 sha256；失败即停，写 trace。
- **理由**：当前数据量 806 行、9 步全链 1–2 秒，DAG 的并行收益抵不过调试与审计成本；顺序计划让“第几步为什么跑”可以直接进答辩。
- **代价**：将来要并行或条件分支，需要把 `plans.py` 升级为带依赖的 DAG；现在不预留伪并行。

## D15 守卫 fail-closed，放在建议之后、案例与报告之前
- **背景**：建议是唯一会“说给人听”的产物，最容易出现证据对不上、低置信硬推、文案泄答案或个人信息。
- **决定**：`src/guards.py` 做 5 类检查（学生覆盖、证据可解析、置信度不变量、答案与合规、个人信息）；任一失败退出码 1；`guard` 工具插在 `recommend` 与 `cases/report` 之间。
- **理由**：让不可核对的建议无法进入案例、报告和契约交付；失败信息保留前 20 条，便于定位。
- **代价**：新增建议类型或文案模板时要同步扩守卫规则，否则会被误拦。

## D16 置信度动作闸门：n<5 只复习/观察
- **背景**：抽样数据里多数指标只有 1–4 条观测，直接排“练这个薄弱点”等于把波动写成结论。
- **决定**：只有 `observed >= 5 且 rate < 0.6` 的指标才允许 practice/variant；`observed < 5` 的弱项只给 review + observe；无已评记录的学生全部 observe。
- **理由**：与 D7 的 5/10 阈值一致，把“缺少记录不等于未掌握”变成可机检的不变量，而不是文案承诺。
- **代价**：部分学生建议条数偏少（本数据 2–4 条为主），需要用 next_check 说明补观察后再调整。

## D17 v1 不接大模型，先把确定性链路做扎实
- **背景**：赛题允许但不要求特定技术；大模型接入会引入密钥、网络、合规与不可复现四类风险。
- **决定**：v1 全部规则与统计生成，不调用任何 LLM；自然语言报告由模板拼装；后续若接入，只允许改写文字，不得改数字、材料与顺序，并必须过 D15 守卫。
- **理由**：材料评审 80% 看结果准确与依据充分；先保证任何评委按命令能复跑出同一结果。
- **代价**：文案偏“工程腔”，答辩时需要人工润色；这部分放在 PDF/PPT，不放进契约。

## D18 可视化选择“本地浏览器工作台”，不做桌面 GUI
- **背景**：需要把 18 个 JSON 产物变成教师能点、评委能核对的界面；团队只有 Python，没有前端构建链预算。
- **决定**：`src/ui_server.py` 用标准库 `http.server` 提供静态文件与 JSON 快照，前端用原生 ES Module + CSS；双击 `run_ui.cmd` 启动并自动开浏览器。
- **理由**：零第三方依赖、零构建步骤，评委拿到仓库即可运行；页面与契约解耦，换数据不用改前端；后续可用 PyInstaller 打包。
- **代价**：没有组件框架与图表库，复杂交互要手写；移动端需自行处理表格与网格溢出。

## D19 工作台只读快照，重跑是显式动作
- **背景**：演示时既要“打开就能看”，又要证明结果可重建；若页面加载即跑流水线，会拖慢打开且难以复现。
- **决定**：`GET /api/snapshot` 只读 `out/` 与清洗版 CSV；缺 7 个核心产物时返回 503 并列出缺失项；“重新分析”才 `POST /api/run` 调既有 9 步流水线，单实例后台运行，前端 1200ms 轮询。
- **理由**：浏览与计算分离，页面不会偷偷改变数据；重跑仍走 clean→…→validate，口径与 CLI 完全一致。
- **代价**：快照可能落后于磁盘上的最新产物，需要用户点“刷新”；运行中重复点击只返回 409。

## D20 零图表库：CSS/内联 SVG 承担全部可视化
- **背景**：引入 ECharts/Chart.js 会增加打包体积、离线不可用风险与供应链披露成本。
- **决定**：KPI 用数字+进度条，热力图用 3×3 CSS Grid，学生得分用 SVG 圆环，班级对比用双列条，时间线用 CSS；不加载任何外链资源。
- **理由**：赛题评分看“结果准确、依据充分”，图表只是载体；原生实现可离线、可打印、可审阅，且不会因库升级改变渲染。
- **代价**：复杂交互（缩放、联动、导出图片）需要自己实现；当前只覆盖本赛题需要的 3 类图。

## D21 桌面交付采用“原生窗口 + 内嵌快照”的单文件 EXE
- **背景**：评审现场双击 `run_ui.cmd` 仍需要 Python 与命令行；需要一个不解释环境、双击即开的本地程序，同时不重写五页界面（后由 D22 增数据录入页、D26 增教学咨询页，现为七页）。
- **决定**：新增 `src/desktop.py`，用 pywebview/Edge WebView2 承载现有 HTML 工作台，PyInstaller `--onefile --windowed` 打包为 `dist/智慧学伴.exe`；内嵌 `ui/`、`out/` 与清洗版 CSV。打包态由 `IS_FROZEN` 标记为只读，`POST /api/run` 返回 409 `read_only_build`，页面按钮改为“只读快照”。
- **理由**：复用 D18 的零构建前端与全部快照/安全逻辑；目标机器不需要 Python；演示时不会出现“按钮能点但跑不起来”的假功能。重跑仍由源码版 `run.cmd all` 负责，职责清晰。
- **代价**：单文件启动需解压，比源码版慢 1–3 秒；数据更新后必须重新构建；Windows 依赖 WebView2 Runtime（缺失时回退默认浏览器）；未签名，首次运行可能触发 SmartScreen。
- **边界**：这不改变 D18“不做原生 GUI 重写”的判断——仍是同一套 HTML 工作台，只是换成原生窗口承载。
## D22 数据录入写独立副本，不碰原始数据与官方产物
- **背景**：需要一个“字段与作答记录完全一致”的输入接口，但原始数据是唯一真相，官方诊断又已固定在清洗版上。
- **决定**：新增 `src/record_input.py`，只写 `data/input/作答记录_录入.csv`（打包态写 `%LOCALAPPDATA%/SmartCompanion/input`）；不写 `data/raw/`，不自动并入 `data/derived/`，也不触发官方诊断。
- **理由**：把“演练/录入”与“交付/复核”隔离；接口可以自由试错，评委仍能按 `run.cmd all` 复现同一结果。
- **代价**：录入数据不会自动改善诊断，需要教师显式导出并走正式清洗；多了一个需要备份的目录。

## D23 录入校验分“硬错误/警告”两级，写操作只开本机
- **背景**：原始 806 行本身带 7 条异常；若所有异常都阻断保存，就演示不了“先发现、再处理”的流程。
- **决定**：表头/列数/必填/ID/外键/事件编号/状态/得分与评分点互斥等为硬错误，返回 422 且不动旧副本；主题不符、材料不在节点、得分超满分、评分点合计不符等为警告，允许保存并逐条展示。写接口仅监听回环地址，要求 `Host`/`Origin` 合法且带 `X-DSH-UI: 1`。
- **理由**：硬错误保证副本仍能被既有质检/清洗链路读取；警告保留真实数据的“脏”，让数据质量页有可核对的对象。
- **代价**：教师必须先读警告再保存；接口没有账号体系，只适合单机使用，不能直接暴露到局域网。

## D24 知识网络采用确定性分层布局，不做力导向与语义边
- **背景**：内容图谱需要一个类似 Obsidian 的节点网络，把主题、指标、课标、材料串起来；初版力导向在 1000×640 画布上把同一主题的 3 个指标挤到 15–30px 内，标签重叠不可读。
- **决定**：新增 `src/graph_model.py` 只把 `content_map` 的显式关系投影为节点/边；前端用确定性三列布局（主题 y=96、指标 y=300、课标 y=540，材料围绕主指标半径 54），不使用 `Math.random` 或力导向；不抽取 PDF 正文、不做语义相似度边。
- **理由**：教师需要的是可读、可核对的“要求—指标—材料”路径，不是装饰性的有机图；确定性布局双跑一致，便于截图、打印和答辩复核。
- **代价**：布局不如力导向“自然”，主题/指标数量变化时要调整分层参数；材料节点密集时只能靠缩放、悬停与搜索辨认。

## D25 知识网络是快照投影，不新增流水线步骤与 out 产物
- **背景**：图谱只是 `content_map` 的另一种读法；若新增第 10 个 agent 步骤或独立 `out/graph.json`，会扩大契约面并让重跑更慢。
- **决定**：在 `ui_server.build_snapshot()` 内调用 `graph_model.build()`，把 `graph` 放进 `ui.snapshot/1`；不写新的 `out/` 文件，不改三份业务契约；旧快照缺 `graph` 时内容页显示缺省提示，其余页面正常。
- **理由**：图谱与内容图谱同源、同生命周期，不需要额外生成与校验；投影是纯函数，可单测、可复算。
- **代价**：快照体积增加约数十 KB；其他消费者若需要图谱，必须复用该投影函数而不是读一个独立文件。

## D26 教学咨询是可选旁路，不进入 9 步流水线与契约
- **背景**：教师需要一个能追问“下一步怎么排、共性弱项怎么讲”的入口；但诊断、建议、报告必须保持可复现，不能因模型输出而变化。
- **决定**：新增 `src/consult.py` 与 `#/consult` 页面，通过 `/api/consult` 调用 DeepSeek；咨询结果只显示在浏览器线程中，不写 `out/`、不改三份业务契约、不增加 agent 步骤，也不把模型回答当作学生证据。
- **理由**：确定性链路是评审复核的基线；把生成式能力放在旁路，既回应真实教学追问，又不牺牲可复算性。
- **代价**：需要网络与 API Key 才能用；回答质量依赖模型，必须由教师复核；离线演示时该页显示未配置。

## D27 咨询配置只在服务端，Key 不进浏览器与仓库
- **背景**：浏览器端持有 Key 会出现在开发者工具、截图和打包资源中；仓库提交真实 Key 会泄露。
- **决定**：配置优先级为环境变量 `DEEPSEEK_API_KEY/BASE_URL/MODEL/TIMEOUT` > `config/consult.json` > 默认；真实配置 `config/consult.json` 加入 `.gitignore`，只提交 `config/consult.example.json`；打包态读 `%LOCALAPPDATA%\SmartCompanion\consult.json`；`/api/consult/status` 只返回是否配置、模型、接口地址与超时，不返回 Key。
- **理由**：Key 只在本地服务进程内使用，浏览器拿不到；换机器时用环境变量即可，不必改代码。
- **代价**：部署者需要自己配置 Key；配置错误只能在服务端日志或状态页排查。

## D28 咨询上下文按白名单聚合，默认不发学生数据
- **背景**：模型要给出贴合学情的建议，但作答原文、参考答案与个人信息不应离开本机分析链路。
- **决定**：默认只发送课程内容、指标、课标与材料编号；只有用户显式勾选学生时才追加该生的聚合诊断（记录数、已评数、覆盖度、指标观测数与得分率、标记、已有建议摘要）；不发送学生最终作答、解答过程、评分点、参考答案、姓名/联系方式；请求体 64 KB 上限、最多 12 轮历史，单实例锁避免并发。
- **理由**：聚合摘要足以支撑教学动作建议，同时把隐私面压到最小；白名单也让上下文可审计、可测试。
- **代价**：模型看不到具体错步，复杂个例仍需教师补充描述；上下文字符上限会截断过长材料。

## D29 公开演示用静态快照，不启动后端
- **背景**：需要让评委、同学在 Mac/手机上直接打开，而不是每台机器装 Python 或只给一个 Windows EXE；但录入、咨询、重跑都依赖本机服务，不能暴露公网。
- **决定**：新增 `src/demo_site.py`，把 `ui/` 与一次 `ui_server.build_snapshot()` 快照复制到 `demo/`，写 `window.DSH_DEMO = true`；演示态隐藏录入/咨询/重跑，前端只读 `snapshot.json`，不保留任何 API 调用路径；`test_demo_site.py` 断言目录只含前端与快照。
- **理由**：静态托管零运维、跨平台、无 Key 泄露面；页面与本地工作台同源，演示与截图不会“两套 UI”。
- **代价**：每次数据更新都要重新生成并提交 `demo/`；演示数据可能落后于最新 `out/`；快照体积约 0.6 MB。

## D30 公开演示用 raw.githack，不启用 GitHub Pages
- **背景**：GitHub Pages 需要改仓库设置、可能引入构建分支；项目只需要托管一个静态目录。
- **决定**：主地址用 `https://raw.githack.com/DG-host/education_agent/main/demo/index.html`，备用 jsDelivr；更新靠提交 `demo/`，缓存用 `?v=` 或 commit sha 规避；不改仓库 Pages 设置。
- **理由**：零配置、直接读仓库文件、支持自定义分支/commit；失败时容易回退到本地 `python -m http.server`。
- **代价**：依赖第三方 CDN 的可用性与缓存策略；仓库必须保持 public。**边界**：`demo/` 的脱敏只覆盖快照，不改变 `data/raw/`、`data/derived/` 在公开仓库中的可见性；若这些文件不能公开，必须改用独立公开仓库。
